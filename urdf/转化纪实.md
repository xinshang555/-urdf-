## 一、任务与已知条件

**输入**
- `model/car.STEP` —— 装配体几何(3 实体 / 5 实例)
- `质量属性/{body,leg1,leg2,wheel1,wheel2}.txt` —— SolidWorks 质量报告
- 运动逻辑已在源文件中设定好,不需要我设计

**目标**
- 有效的 URDF(几何、质量、惯量正确,装配不散)
- 由此生成 MJCF,能在 MuJoCo 打开

**起点约束**:用户明确说"质量不准确",所以质量以报告为准;几何以 STEP 为准。

---

## 二、第一步:先把"到底有几个零件"钉死

不看任何转出来的中间文件,**回到 STEP 原文数**:

```
PRODUCT 'car'              ← 装配体
PRODUCT 'body'             ← 零件
PRODUCT 'leg'              ← 零件
PRODUCT 'wheel_defeature'  ← 零件
MANIFOLD_SOLID_BREP = 3    ← 只有 3 个实体!

NEXT_ASSEMBLY_USAGE_OCCURRENCE 5 条:
    NAUO1 → body
    NAUO2 → leg
    NAUO3 → wheel
    NAUO4 → leg      ← 同一零件的第 2 个实例
    NAUO5 → wheel    ← 同一零件的第 2 个实例
```

**结论:5 个实例 = 3 种零件。** 1 车体 + 2 腿 + 2 轮。

> 这一步后来证明是**必要的**:用户看到导出的 5 个 STL,以为"我把车拆成了 5 块"。
> 有了 STEP 原文的实体数,才能明确说"5 个文件 = 5 个装配实例,不是被切碎"。

## 三、第二步:量出几何真值(不猜)

从 STEP 的圆柱面 + 装配变换反解关键尺寸,每一条都要求**可复现到 1e-6 mm**:

| 量 | 结果 |
|---|---|
| 髋轴孔 → 轮轴孔节距 | **40.000000 mm** |
| 轮外半径 | **8.000 mm** |
| 轮宽 | 7.000 mm |
| 两轮横向间距 | **39.000000 mm** |
| 车身 | 40 × 25 × 35 mm |
| 髋轴位置 | Z = 0.0 / 31.5 |
| 轮中心 | Z = −2.0 / +37.0 |

**镜像自检**:两轮中心 Z 之和 = −2.0 + 37.0 = **+35.0** = 2 × 17.5(车身中平面)✅

这条约束后来成了装配门禁里的固定检查项。

## 四、第三步:坐标系设计 —— 只平移,不加旋转

**设计**:URDF 沿用 CAD 装配轴(X 前后 / Y 竖直 / Z 侧向),每个 link 的锚点选在**物理转轴**上:

| 零件 | 锚点 | 理由 |
|---|---|---|
| body | CAD (0,0,0) | 天然基准 |
| leg_* | 髋关节孔中心 | 关节转轴 |
| wheel_* | 轮轴中心 | 关节转轴 |

网格 = 装配坐标 − 锚点,**纯平移**。这样"网格→link"没有任何旋转可以出错。

**当时的心态**:我以为这样最省事、最不容易错——把复杂度全压到关节 origin 里。

---

## 五、第四步:发现上轮"不是平移关系",于是走了弯路

量出来上轮和下轮姿态不同,我判断"两轮互为镜像",于是给上轮加了 180° 绕 Y 旋转。

**这个判断是错的。** 而且我当时的**验证方式**也是错的:

```python
# 我把 part_003 绕自身包围盒中心转 180°,再平移到 part_005 的中心,
# 然后比最近点距离 —— 得到 0.000001 mm,判定"匹配"
```

**为什么这个验证是假阳性**:轮子在 XY 平面上是**圆盘**,绕 Z 自转任意角度都几乎不影响点云匹配。我用"先转到包围盒中心再平移"的方式,把一个 30° 的自转差异**吸收掉了**。

> 教训:**对回转体,点云匹配无法判别绕自身轴的角度。**
> 要么用显式特征(键槽、轮毂凸台朝向),要么干脆不要加旋转。

---

## 六、第五步:翻车 —— 用户说"你把车拆成零件了吗"

打开 viewer,用户看到的是散开的零件。我回头量**相邻零件最近顶点距离**:

| 零件对 | 我的 URDF | CAD 原始 |
|---|---|---|
| body ↔ leg_lower | 6.16 mm | 0.265 mm |
| leg_lower ↔ wheel_lower | **13.11 mm** | 0.189 mm |
| body ↔ leg_upper | 3.35 mm | 0.265 mm |
| leg_upper ↔ wheel_upper | **17.19 mm** | 0.189 mm |

**而在此之前,我所有的检查都是通过的**:

```
包围盒 vs CAD      误差 0.000000 mm   ✅
质量 / 密度 / 惯量  全部一致           ✅
质量矩阵 / qfrc_bias 一致到 1e-16      ✅
49 项结构检查       0 failed           ✅
```

### 为什么这些检查全部失效

因为它们**都是"一个零件一个零件"地看**。

包围盒是**稀疏描述** —— 把零件平移一段,包围盒可能完全不变。所以"包围盒对上"这件事,在零件错位时**照样成立,纯属巧合**。

> **这是整件事最核心的教训:**
> **逐零件正确 ≠ 装配正确。必须单独检查"零件之间的关系"。**

---

## 七、第六步:把错误逼出来的方法

既然原来的检查抓不到,就换一类检查。我按"由粗到细"逐层收紧:

### 7.1 顶点级最近距离(抓相对错位)

```python
d, _ = cKDTree(V[b]).query(V[a])
gap = d.min()
```

立刻暴露:轮子离腿 13 mm。

### 7.2 绝对包围盒(抓整体平移)

相对间隙有个盲区:把**整条腿一起平移 5 mm**,腿长 48 mm,平移后**仍与车身重叠** —— 间隙检查看不见。

所以补了绝对位置约束。**这一条是在给门禁写自测时才发现的**:我故意注入"腿偏移 5 mm",门禁**没报警**。

### 7.3 正运动学 vs 手算(抓旋转符号)

把 MuJoCo 的 FK 结果和手算 `Rx(+90°) @ CAD_pos` 逐件对比:

```
leg_lower    err 0.0000 mm  ✅
wheel_upper  err 0.0000 mm  ✅
```

这一步确认了**坐标系本身没错**,错位来自别处。

### 7.4 渲染连通块计数(抓"看起来散了")

把机器人单独渲染,数连通块。修好后:

```
front 1 块 | side 1 块 | top 1 块     ← 修好前是 5 / 3 / 2 块
```

> 细节:0.2 mm 的配合间隙在 620 px 画面里约 0.6 px,可能把一块切成两块。
> 所以判据是"**膨胀 1~2 px 后仍为 1 块**"。

## 八、第七步:找到三个真凶

### 真凶 1:上轮锚点用错

```
我写的       WHL_UP_BORE  Z = 31.5   ← 这是腿的间距
实际轴线     Z = 35.0
```

轮子是"轮盘 + 轮毂"结构,**轮毂凸台才是装配面**。我拿腿的间距当了轮轴位置,轮子挂在轴外 3.5 mm。

### 真凶 2:多余的旋转

第五步加的那个 180°。**源网格本来就是正确的装配坐标,原样用就行。**

证明方式:把 5 个源网格**不做任何变换**直接摆在一起量间隙:

```
body      <-> leg_lower      0.264890 mm   贴合
leg_lower <-> wheel_lower    0.189207 mm   贴合
body      <-> leg_upper      0.264890 mm   贴合
leg_upper <-> wheel_upper    0.189207 mm   贴合
```

**全部贴合。** 说明源网格就是装配体,任何我加的变换都是破坏。

> 判别法:**加了变换后间隙变大 → 变换就是错的。**

### 真凶 3(最隐蔽):MJCF 的 geom 抄了编译后的坐标系

`make_mjcf.py` 里我这么写:

```python
gattr.append(f'quat="{mp.geom_quat[gid]}"')     # ❌
```

**为什么错**:MuJoCo 编译 URDF 时会**重新表达每个 geom 的坐标系**,好让惯量主轴落位。那些值**不是** URDF 的 `<visual><origin>`。

结果:腿的 geom 带上 `quat=[0.511, 0.489, -0.511, 0.489]`,**118° 误差**,腿被放倒。

**修复**:geom 不抄编译值;但要把 MuJoCo **折叠掉的 fixed 关节旋转**补到父 body 上:

```python
# car_zup.urdf: mount_to_body 是 fixed, rpy = +90° 绕 X
# MuJoCo 把旋转推给子 body,mount 却不转,但仍持有 body 的网格
if nm == "mount" and folded_fixed_rot is not None:
    gq = folded_fixed_rot
```

## 九、第八步:验证 MJCF 等价性(两次踩坑)

### 坑 A:比了两个积分器

URDF 没有 `<option>`,MuJoCo 用默认 `dt=2ms / Euler`;
我的 MJCF 写 `dt=0.5ms / implicitfast`。

直接比 → 报出**假的 1743 m/s² 失配**。

**修复**:对齐 `opt.timestep` / `opt.integrator` 再比。

### 坑 B:接触在暗中捣乱

对齐后 1000 步仍有 0.345 的差。逐层排查:

| 嫌疑 | 验证 | 结果 |
|---|---|---|
| 模型不同? | 同一 qpos 下比 M | 差 **1.5e-16** → 模型相同 |
| 地面接触? | 关掉 floor 的 contype | 仍差 |
| **自碰撞** | 逐对打印 contact | 第 690 步 `mount` 撞上 `wheel_upper` |
| 混沌? | 同模型跑 1e-12 扰动 | 2000 步后仅 **1.004e-12** → **不是混沌** |
| **关节限位** | 逐 25 步打印 | 第 1322 步 `qpos[7]` 撞 ±0.8 |

**"同模型 + 1e-12 扰动"是判别混沌的关键手段**:
- 若 1e-12 也放大 → 混沌,是精度极限,不必追
- 若 1e-12 不动而两模型发散 → **有真差异**,继续查

本项目实测(`tools/chaos_recheck.py` 可复现):

```
初值差 1e-12  →  2000 步后 1.004e-12   (只放大 1.004 倍)
而 URDF vs MJCF 在同一时刻差 2.6e-2    (放大 2.6e10 倍)
```

两者相差 **十个数量级**,所以**不是混沌** —— 一定是某个离散事件。查下去正是关节限位。

最终把比较方式改成**在相同随机状态下比**(而不是比漫长轨迹):

```
|dM|         ≤ 1.5e-16
|dqfrc_bias| ≤ 4.6e-15
|dqacc|      ≤ 2.0e-09
```

## 十一、方法论总结

### 三类检查,层层递进

| 层级 | 抓什么 | 本项目结局 |
|---|---|---|
| 单零件(包围盒/质量/密度) | 网格坏、单位错 | ✅ 全过,**但没发现散架** |
| 坐标系(正运动学 vs 手算) | 旋转符号、轴向 | ✅ 全过,**但没发现散架** |
| **装配连接性(顶点距离)** | **零件散落** | ← **只有这一层抓到了** |

### 五条硬规则

1. **源网格保持装配坐标,不要居中、不要加旋转**
   加变换后间隙变大 → 变换就是错的

2. **不要用点云匹配验证回转体的角度**
   圆盘绕自身轴任意转都"匹配"—— 这是假阳性

3. **相对间隙 + 绝对包围盒,两条都要**
   整体平移能骗过相对检查

4. **生成脚本里做成硬门禁,不要只 print 警告**
   散架的 URDF 毫无用处,而所有单零件检查都会通过

5. **检查工具要给自己写"注入 bug"的自测**
   我写门禁时,自测立刻发现"腿整体平移 5 mm"漏检 → 才补了绝对位置约束

### 两个判别技巧

- **混沌 vs 真差异**:同模型跑 1e-12 扰动
- **配置错 vs 物理**:对齐 `<option>`、关掉接触再比
